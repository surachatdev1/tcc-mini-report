# เปิด–ปิดการรับแบบประเมิน

Firebase production: เข้าสู่ระบบด้วยบัญชี Admin ที่ `/admin` แล้วใช้ส่วน **เปิด–ปิดการรับแบบประเมิน** ด้านบนของหน้าจัดการ

| โรงเรียน | หน่วยงานระดับพื้นที่ | ผล |
| --- | --- | --- |
| เปิด | เปิด | รับทั้งสองกลุ่ม |
| เปิด | ปิด | รับเฉพาะโรงเรียน (รถรับส่ง ทัศนศึกษา จักรยานยนต์) |
| ปิด | เปิด | รับเฉพาะหน่วยงานระดับพื้นที่ทั้งสี่ประเภท |
| ปิด | ปิด | หยุดรับทั้งหมด |

แต่ละสวิตช์บันทึกทันที ไม่มีการลบผลประเมินเดิม ไม่มีผลต่อการอ่าน Dashboard หรือการส่งออก Excel ผู้ตอบที่เปิดหน้าค้างไว้ได้รับสถานะใหม่ และ Firestore Rules ตรวจอีกครั้งตอนเขียน จึงไม่สามารถใช้หน้าเว็บเก่าข้ามการปิดรับได้ หากปิดระหว่างทำ ร่างยังอยู่ในเครื่องเดิม

สถานะอยู่ที่ `assessment_settings/availability`: schemaVersion 1, school/agency เป็น boolean, updatedAt และ updatedBy. อ่านเฉพาะเอกสารนี้ได้แบบสาธารณะ แต่เขียนได้เฉพาะ Admin ที่ยืนยันอีเมลแล้ว ไม่อนุญาตลบเอกสารเพื่อย้อนกลับไปเปิดอัตโนมัติ การเปลี่ยนค่าผ่าน transaction รักษาค่าของอีกกลุ่มเมื่อ Admin ทำงานพร้อมกัน

หากยังไม่มีเอกสาร ค่าเริ่มต้นคือเปิดทั้งคู่เพื่อรักษาพฤติกรรมเดิม การโหลดผิดพลาดหรือข้อมูลผิดรูปแบบไม่ถือเป็นเปิดรับ หน้าเว็บรอยืนยันสถานะจากเซิร์ฟเวอร์ก่อนเปิดปุ่มส่ง และอ่านสถานะอีกครั้งก่อนส่งโดยไม่อ่านผลประเมินของคนอื่น หากสถานะเปลี่ยนระหว่างนั้น Rules เป็นตัวตัดสินสุดท้าย

## นำขึ้นระบบ

Deploy Rules พร้อม Hosting ก่อนใช้งานสวิตช์และรหัสโรงเรียนรูปแบบใหม่:

```bash
npm ci
npm run test:firebase
npm run test:rules
npm run firebase:deploy
```

คำสั่ง deploy ใช้ Firebase CLI ที่ล็อกอินแล้วและ `.env` ตามคู่มือ Firebase ของโครงการ หาก deploy เฉพาะ Hosting โดยไม่อัปเดต Rules อาจส่งผลประเมินที่มีรหัสโรงเรียน/เปลี่ยนสถานะไม่ได้ หลัง deploy ให้เข้า Admin เพื่ออัปเดตภาพรวมสาธารณะเป็น schema 3 ก่อนตรวจตัวกรองโรงเรียนชื่อซ้ำ

เดโม Sites/D1 ไม่ใช้แผงตั้งค่า Firebase นี้ ฟีเจอร์นี้ควบคุมปลายทาง Firestore ของเว็บไซต์จริง
