# Safe Travel Assessment

ระบบประเมินตนเองด้านการเดินทางที่ปลอดภัยของเด็กนักเรียน ตามร่างเกณฑ์วันที่ 22 มิถุนายน 2569 รองรับแบบประเมินสถานศึกษา 3 ชุด แบบประเมินหน่วยงานกำกับ 4 ประเภท และ Dashboard สำหรับเจ้าหน้าที่

เอกสารประกอบ: [การตั้งค่า Firebase](docs/FIREBASE_SETUP.md) · [สถาปัตยกรรม Firebase](docs/FIREBASE_ARCHITECTURE.md) · [ที่มารายชื่อสถานศึกษา](docs/SCHOOL_DIRECTORY.md) · [BA traceability](docs/BA-TRACEABILITY.md) · [ที่มาตราสัญลักษณ์](docs/BRAND_ASSETS.md)

## Production target

- Firebase Hosting: เว็บหลักและ `/dashboard`
- Cloud Firestore: เก็บผลประเมินที่ผู้ใช้ยินยอมให้เผยแพร่
- Firebase App Check: ลดการส่งข้อมูลจากสคริปต์หรือเว็บไซต์ปลอม
- Firebase Authentication: ใช้ Google Sign-In ก่อนเข้าดู `/dashboard`
- ชื่อและเบอร์โทรผู้ประเมินจัดเก็บแยก และเปิดอ่านเฉพาะ Admin ส่วนกลาง (Viewer จังหวัดไม่เห็นข้อมูลติดต่อ)
- ไม่ใช้ SQL Connect ในรุ่นนำร่อง

## เริ่มใช้งานบน Firebase

อ่านขั้นตอนทั้งหมดที่ [docs/FIREBASE_SETUP.md](docs/FIREBASE_SETUP.md)

```bash
cp .env.firebase.example .env.local
npm run firebase:build
firebase login
npm run firebase:deploy
```

## คำสั่งสำคัญ

- `npm run firebase:build` สร้าง static SPA ใน `firebase-dist/`
- `npm run firebase:serve` เปิด Firebase Hosting และ Firestore Emulator
- `npm run firebase:deploy` build และ deploy Hosting พร้อม Firestore rules/indexes
- `npm run firebase:smoke` ตรวจหน้าเว็บและ route สำคัญหลัง deploy
- `npm run firebase:release` ตรวจโค้ด ทดสอบ Deploy และ Smoke test ครบในคำสั่งเดียว
- `npm run schools:import` อัปเดตรายชื่อสถานศึกษา 12 จังหวัดจากข้อมูลภาครัฐ
- `npm test` ตรวจ Firebase build สูตรคะแนน ความครบถ้วนของเกณฑ์ และข้อมูลสถานศึกษา
- `npm run test:rules` ตรวจการส่งแบบประเมินครบทุกประเภทและสิทธิ์ข้อมูลกับ Firestore Emulator (ต้องมี Java 21+) โดยไม่เขียนข้อมูลเข้าโปรเจกต์จริง
- `npm run test:sites` ตรวจ build ของ Sites เฉพาะใน checkout ที่มี `.openai/hosting.json`

## หลักการข้อมูล

- ร่างที่ยังไม่ยืนยันอยู่ใน `localStorage` ของอุปกรณ์
- ผลที่ยืนยันเก็บแบบสร้างครั้งเดียวใน `submissions/{idempotencyKey}`
- ชื่อ บทบาท ตำแหน่ง และเบอร์โทรผู้ประเมินเก็บแยกใน `submission_assessors/{idempotencyKey}` และเปิดอ่านเฉพาะ Admin ส่วนกลาง
- ไม่เก็บคะแนนรวมจาก client; Dashboard คำนวณใหม่จากคำตอบดิบตามเกณฑ์ในโค้ด
- Firestore Rules ให้ Admin อ่านทุกจังหวัด ส่วน Viewer รายอีเมลอ่านได้เฉพาะจังหวัดที่บันทึกใน `dashboard_members` หรืออนุมานตรงตัวจากชื่อหน่วยงานเดิม; ข้อมูลติดต่ออ่านได้เฉพาะ Admin และแก้ไขหรือลบจาก Viewer ไม่ได้
- หน้า `/admin` แสดงแบบประเมินหนึ่งชุดต่อหนึ่งรายการ และให้ Admin ลบทั้งชุดหรือลบทั้งหมดผ่านหน้าต่างยืนยัน รวมถึงลบข้อมูลผู้ประเมินที่เชื่อมโยงกัน
- หน้าผลลัพธ์ใช้ `benchmarks` เปรียบเทียบกับค่ากลางเฉพาะกลุ่มที่มีอย่างน้อย 10 ผลประเมิน; หากไม่ถึงจะแสดงเทียบขั้นมาตรฐาน
- หน้าแบบประเมินยังเปิดให้ประชาชนกรอกได้โดยไม่ต้องล็อกอิน

รายละเอียดโครงสร้างอยู่ที่ [docs/FIREBASE_ARCHITECTURE.md](docs/FIREBASE_ARCHITECTURE.md)

## การค้นหาขั้นสูงใน Dashboard

เลือกโรงเรียน/หน่วยงาน สังกัด จังหวัด ประเภท ผู้รับผิดชอบ ระดับผล และช่วงวันที่ประเมิน แล้วกดค้นหา ระบบใช้ทุกเงื่อนไขร่วมกันกับตาราง สรุปผล และ Excel รายการเลือกแสดงหน้าละ 10/20/50/100 ชุด (เริ่มต้น 20) พร้อมเลขหน้าและปุ่มไปหน้าแรก/สุดท้าย กดหัวคอลัมน์หรือเลือกช่องเรียงตามเพื่อเรียงขึ้น–ลง โดยเรียงทุกชุดก่อนแบ่งหน้า Excel ส่งออกทุกชุดที่ตรงกับเงื่อนไขตามลำดับเดียวกับตาราง ผู้ที่ไม่มีสิทธิ์ดูข้อมูลส่วนบุคคลจะไม่เห็นตัวกรองชื่อผู้รับผิดชอบ

สังกัดจับคู่ชื่อโรงเรียนและจังหวัดกับทะเบียนที่มีในระบบ รองรับ สพฐ. และเอกชน ไม่ใช่ข้อมูลเขตพื้นที่การศึกษาอย่างละเอียด หากไม่พบชื่อหรือพบชื่อซ้ำต่างสังกัดจะแสดงว่าไม่พบข้อมูลสังกัด โดยไม่แก้ข้อมูลเดิมใน Firestore

ตารางคงคอลัมน์เลขอ้างอิง สถานศึกษา/หน่วยงาน จังหวัด แบบประเมิน ผู้ให้ข้อมูล หน้าที่/ตำแหน่ง เบอร์โทร วันที่ และผลเหมือนเดิม การค้นหาเริ่มต้นเป็น Search all และแยกช่องเลขอ้างอิง ชื่อ หน้าที่/ตำแหน่ง และเบอร์โทร ปุ่ม Export ผลค้นหาที่ตารางส่งออกทุกรายการที่ตรงเงื่อนไขครบทุกหน้า โดยเคารพสิทธิ์ข้อมูลส่วนบุคคล

## ระดับสิทธิ์ผู้ดูแลและเจ้าหน้าที่จังหวัด

- **Super Admin**: บัญชีเจ้าของโครงการ 3 บัญชีที่กำหนดถาวรใน `lib/access-roles.ts`; ดู/Export ทุกจังหวัด รวมข้อมูลติดต่อ จัดการผู้ใช้ ลบข้อมูล และเผยแพร่ภาพรวมได้
- **Admin ส่วนกลาง**: เพิ่มได้โดย Super Admin ผ่าน `/admin`; เก็บใน `dashboard_members/{email}` ด้วย `schemaVersion: 3`, `role: admin`, `province: null` มีสิทธิ์ดู/Export ทุกจังหวัด แต่ไม่เห็นข้อมูลติดต่อและไม่มีสิทธิ์จัดการ/ลบ/เผยแพร่
- **เจ้าหน้าที่จังหวัด**: ใช้ `role: province_viewer` กับชื่อจังหวัดที่บันทึกไว้ ดู/Export ได้เฉพาะจังหวัดที่ได้รับมอบหมายเท่านั้น โดยจำกัดทั้ง Firestore Query และ Firestore Rules

บัญชีที่เพิ่มใหม่ต้องเลือก Role ให้ตรงหน้าที่ หากเป็นเจ้าหน้าที่จังหวัดต้องระบุจังหวัดจาก 12 จังหวัดนำร่อง หากเป็น Admin ส่วนกลางไม่ต้องระบุจังหวัด และ Super Admin ยังคงเป็นรายชื่อถาวร (ไม่สามารถยกระดับผ่านการแก้ไข Role ใน `dashboard_members`)

สำหรับบัญชีเดิมที่ไม่มี `role` (schema 1/2) ระบบรักษาสิทธิ์เฉพาะจังหวัดไว้เหมือนเดิม หากชื่อหน่วยงานตรงรูปแบบ `หน่วยงานประจำจังหวัดกาญจนบุรี` หรือ `หน่วยงานประจำจังหวัด กาญจนบุรี` เมื่อ Super Admin เปิด `/admin` จะบันทึกจังหวัดและ `role: province_viewer` ด้วย Firestore transaction โดยไม่เพิ่มสิทธิ์ส่วนกลางให้ผู้ใช้เดิมโดยอัตโนมัติ

`/dashboard` สำหรับ Admin/Super Admin แสดงข้อมูลทุกจังหวัดและ Export ตามตัวกรอง ส่วนเจ้าหน้าที่จังหวัดใช้ Firestore `where("province", "==", assignedProvince)` และถูกตรวจซ้ำใน Rules แม้จะปรับ UI เองก็ไม่สามารถเรียกผลประเมินข้ามจังหวัดได้ ข้อมูล `submission_assessors` อนุญาตให้เฉพาะ Super Admin อ่านได้ ส่วน `/dashboard/overview` เป็นภาพรวมสาธารณะตามนโยบายเดิม

ก่อน Merge/Deploy ให้ตรวจ `npm run lint`, `npm run test:firebase` และ `npm run test:rules` บนสภาพแวดล้อมที่มี Node.js และ Java/Firebase Emulator พร้อมใช้งาน
